# 四字熟語カルタ Web版プロトタイプ

## 1. プロジェクト概要

四字熟語カルタの読み上げを支援するWebアプリを開発する。

カルタで使用する読み札の文章を音声で読み上げることで、読み手がいなくても家族や友人だけで四字熟語カルタを楽しめるようにする。

現在はAlexa Skill版を開発しており、音声による操作と読み上げを試している。

しかし、実際にAlexa版を使用する中で、音声UIそのものがカルタというゲームに最適なのかという課題が見えてきた。

そのため、次の段階として、

> **「画面で操作し、音声で読み上げる」**

という方式をWebアプリとしてプロトタイプし、実際のゲーム体験を検証する。

---

## 2. 背景と課題

Alexa版では、音声によって次の札を読み上げる操作ができる。

しかし、カルタは家族や友人同士が自然に会話しながら遊ぶゲームであるため、音声による操作には以下の問題がある。

- 正確に発話しないと認識されない
- ゲーム中の自然な会話が音声コマンドとして誤認識される可能性がある
- 「次」などのトリガーとなる言葉を会話中に発した場合、意図せず次の札を読み上げる可能性がある
- 音声操作のために、プレイヤーがゲーム中の会話を意識的に制限する必要が生じる

そこで、音声を「操作」のために使用するのではなく、

**操作は画面、出力は音声**

と分離する方式を検証する。

---

## 3. Phase 1の仮説

以下のゲーム体験を仮説とする。

1. スマートフォンをカルタをする人たちの中央または端に置く
2. Webアプリを開く
3. 「ゲーム開始」をタップする
4. プレイヤーが札を準備する
5. 「次の札を読む」ボタンをタップする
6. 約1秒後に読み上げを開始する
7. プレイヤーは読み上げられた文章を聞いて札を取る
8. 読み上げ終了後、再び「次の札を読む」をタップする
9. これを繰り返す

この方式であれば、ゲーム中の家族同士の会話とアプリの操作を分離できるため、音声UIよりも自然にカルタを遊べる可能性がある。

---

## 4. Phase 1の目的

Phase 1の目的は、完成したサービスを作ることではない。

**「画面で操作して、音声で読み上げる」というゲーム体験が実際に使いやすいかを検証すること**を目的とする。

特に以下を実際のゲームで確認する。

- ボタンを押す操作は自然か
- スマートフォンをカルタの中央・端に置いたとき操作しやすいか
- 「次の札を読む」ボタンは押しやすいか
- 約1秒の待ち時間は適切か
- 読み上げの速度は適切か
- スピーカーの音量は十分か
- 家族の会話を邪魔せずに遊べるか
- 読み手がいなくてもゲームとして成立するか

---

## 5. 技術方針

### 5.1 Webアプリ

GitHub Pagesで公開可能な**静的Webアプリ**として実装する。

サーバーサイドの処理はPhase 1では必要としない。

基本構成は以下とする。

```text
HTML
CSS
JavaScript
   ↓
Web Speech API
   ↓
スマートフォンのスピーカー
```

### 5.2 音声読み上げ

Phase 1では音声ファイルを事前生成しない。

ブラウザ標準のWeb Speech API (`speechSynthesis`) を使用して、読み上げ文章をリアルタイムに音声化する。

TTS APIや外部音声生成サービスはPhase 1では導入しない。

目的は音声品質の検証ではなく、**「タップ操作＋音声読み上げ」というUXの検証**だからである。

将来的に必要であれば、TTS APIによる音声ファイルの事前生成へ移行する。

---

## 6. データ

既存のAlexa版には、カルタの読み上げに使用する文章が存在する。

例：

> 太郎君が河に落ちそうになった。危機一髪！

Web版では、可能な限り既存のカルタデータと読み上げ文章を再利用する。

同じデータをAlexa版とWeb版で利用できる場合は共通化を検討する。

ただし、Phase 1では過度なリファクタリングや抽象化は行わない。

### 採用した方針

Phase 1では `lambda/data/scenarios.json` の内容を `web/data/scenarios.json` へそのままコピーして利用する。

ビルドステップや共有ディレクトリへのシンボリックリンクなどの仕組みは導入しない（GitHub Pagesでの静的公開・過度な抽象化の回避を優先するため）。

---

## 7. ディレクトリ構成

現在のAlexa版は削除せず、既存の実装として残す。

Web版はAlexa版とは独立したディレクトリとして追加する。

基本的には以下のような構成を想定する。

```text
/
├── alexa/              # 既存のAlexa Skill
├── web/                # Web版プロトタイプ
│   ├── index.html
│   ├── style.css
│   └── app.js
├── data/                # 既存データを確認して必要に応じて利用
└── プロジェクト概要.md
```

ただし、実際のリポジトリ構成を確認したうえで、既存プロジェクトに最も自然な構成を採用する。

Alexa版を削除したり、Web版への移行を理由として大規模なディレクトリ変更を行ったりしない。

Alexa版は、今回のWeb版プロトタイプに至るまでの実験・比較対象として残す。

### 採用した構成

既存のAlexa版ファイル（`lambda/`, `skill-package/`, `.ask/`, `ask-resources.json`）はルート直下のまま移動しない。

Web版は新規に `web/` ディレクトリを追加する形で導入する。

```text
/
├── lambda/              # 既存のAlexa Skill（Lambda）
├── skill-package/       # 既存のAlexa Skill（manifest・interaction model）
├── web/                 # Web版プロトタイプ
│   ├── index.html
│   ├── style.css
│   ├── app.js
│   └── data/
│       └── scenarios.json
└── README.md
```

## 8. Web版の最低限の機能

### ゲーム開始

「ゲーム開始」ボタンを表示する。

ゲーム開始後は、現在の問題数と「次の札を読む」ボタンを表示する。

### 次の札

「次の札を読む」をタップすると、

1. 次のカードを選択する
2. 約1秒待つ
3. 読み上げ文章を音声合成する

という処理を行う。

### 重複防止

同じ札が連続して読み上げられないようにする。

### 操作中のボタン制御

札の選択中、待機中、読み上げ中など、連続タップによってゲーム状態が壊れないようにする。

### スマートフォン対応

スマートフォンで使用することを前提とする。

特に、

- 大きなボタン
- シンプルな画面
- 視認性
- タップしやすさ

を重視する。

## 9. GitHub Pages

Web版はGitHub Pagesで公開する。

GitHub Pagesでそのままホスティングできるよう、Web版は静的ファイルのみで構成する。

Phase 1では、可能な限りシンプルな公開方法を採用する。

公開後はスマートフォンからアクセスし、実際のカルタで利用できる状態にする。

GitHub Pagesの設定や公開方法については、現在のGitHubリポジトリ構成に合わせてREADMEまたは開発者向けドキュメントに記載する。

## 10. Phase 1でやらないこと

以下はPhase 1では実装しない。

- Alexaとの連携
- 音声による操作
- 音声認識
- TTS API
- 音声ファイルの事前生成
- ユーザー認証
- データベース
- オンライン対戦
- 複雑な設定画面
- 本番用の高度なデザイン
- 課金機能
- 過度なアーキテクチャ設計

## 11. 今後の可能性

Phase 1で実際に家族とゲームを行い、Web版の操作性を検証する。

結果が良ければ、次のフェーズとして音声品質やゲーム体験を改善する。

例えば、

```text
Phase 1
Web Speech API
    ↓
UX検証

Phase 2
TTSサービス比較
    ↓
最適な読み上げ音声を選択

Phase 3
音声ファイルを事前生成
    ↓
安定した音声再生

Phase 4
ゲーム機能・UI・コンテンツの改善
```

などを検討する。

また、Alexa版についても、Web版の検証結果を踏まえて今後の扱いを判断する。

現時点ではAlexa版を廃止することを決定しない。

---

## 12. 開発における重要な考え方

このプロジェクトでは、技術的に高度なものを作ることよりも、

**「実際に家族でカルタを遊んだとき、自然で楽しいか」**

を重視する。

そのため、Phase 1では最小限の実装で実際のゲームに投入し、ユーザー体験から次の改善を決める。

今回のWeb版は完成品ではなく、**ゲーム体験を検証するためのプロトタイプ**である。


## 問題データ

約50個の四字熟語について、あらかじめ読み上げる文章を作成しておく。

各問題は以下の情報を持つ。

- 四字熟語
- 読み方
- 読み上げるシナリオ

シナリオはAlexa Skill側で生成・編集するのではなく、**完成済みの文章をそのまま読み上げる**。

例えば、

```json
{
  "word": "危機一髪",
  "reading": "ききいっぱつ",
  "script": "太郎君が川に落ちそうになりました。あやうく大変なことになるところでした。危機一髪！"
}
```

のようなデータとして管理する。
